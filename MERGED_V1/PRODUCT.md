# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

- 系统管理员：查看并管理全部小区的资产、住户、收费、运营和统计。
- 物业工作人员：在被授权的小区范围内完成同一套物业工作流程。
- 居民用户：仅查看和处理本人关联的居所、房产、账单、通知及异常上报。

## Product Purpose

多小区物业管理系统把房产层级、居住关系、收费、异常、通知、租赁、空间地图和统计集中在一套可操作的本地物业工作平台中。成功标准是让三类用户能够快速理解自己的工作范围、完成任务，并且不越过既有的数据边界。

## Positioning

这不是宣传“智能大脑”的概念页，而是以真实多小区范围、真实账单统计和真实身份权限为基础的物业业务操作系统。

## Operating Context

- 管理端在桌面浏览器中使用，入口包括物业工作台、资产与空间、居民服务、费用管理、物业运营和数据分析。
- 居民端采用顶栏与居中内容区，用于低频查询和异常上报。
- 后端的 `SYSTEM_ADMIN` 全局范围、`PROPERTY_STAFF` 小区 DataScope、`PERSON_USER` personId 隐私边界是不可改变的事实。

## Capabilities and Constraints

- 已有功能包含资产层级、房产、居民/入住、异常、收费/账单、通知、租赁、地图、统计和居民门户。
- 本轮只重构前端信息表达与交互组织；不改数据库模型、业务状态机、JWT、Spring Security、Redis、MinIO 或 AMap。
- 业务枚举可在后端保留英文代码；前端必须统一展示中文业务文案。
- 真实 API 和后端 DataScope 是所有可视化与摘要的唯一数据来源，禁止前端全量获取后过滤或展示虚构业务数据。

## Brand Commitments

- 沿用“栖云物业 / SMART PROPERTY”及深绿、青绿、灰白的识别基础。
- 视觉应专业、安静、规整、有层次；避免深蓝科技大屏、霓虹、营销式“智慧”术语和夸张 KPI 墙。

## Evidence on Hand

- 现有 Vue + Element Plus + ECharts 前端、Spring Boot API、权限与 DataScope 链路。
- 现有真实账单、房产、住户、通知、异常、地图数据；不新增模拟数据。

## Product Principles

1. 先清楚地表达业务范围，再展示数据密度。
2. 功能入口守恒：重组、分组和提炼，不删除有效业务能力。
3. 角色不同，页面体验可不同；权限与数据边界不可不同。
4. 空状态应解释下一步，不用空白填充页面。
5. 图表只承担真实业务问题的回答，不承担装饰。
