## 相对 V1 强化或修正的口径

1. 产权以最终备份为准：V3 的“一房当前一业主、份额为 1”只是当时规则；最终为 share 在 (0,1] 且同一 person+当前房产组合唯一，不提供多人份额合计为 1 的跨行保证。
2. V1—V10 是可见迁移历史，不等于从空库无差异重建最终库。最终 notification、agency_staff 与两财务 View 的初建来源，以及部分生成列变更原文尚不完整。
3. 缺少账单的月份使用 null/no data，不能按 0 元展示；零元账单是另一种存在的业务事实。
4. 单账单财务 View 的两个子集合分别预聚合后才 LEFT JOIN Bill，避免账单项目与多笔付款的乘法重复；SUCCESS 之外的付款不计实收。
5. 物业付款只在账单级聚合，没有费用项目级分摊关系，不能从账单欠费反推“某项费用仍欠多少”。
6. staff_scope_a / staff_scope_c 的 72/168 是历史验收值，不是永远固定的账号属性。
7. 数据卷 down/up 与 SQL/对象抽样证明该批数据可恢复，不等于异地灾备；Redis PONG 不等于业务缓存性能收益。
8. 地图为普通经纬度与高德服务协作，不是已实现 MySQL GIS；MySQL 与 MinIO 也不具有跨系统原子事务。
